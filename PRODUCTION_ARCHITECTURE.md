# Echo Show Remote — Production Architecture

## Current build status

The web bundle and relay syntax both pass CI. The remaining production gate is runtime integration: an Alexa-authenticated relay host, a real `RELAY_TOKEN`, and a deployed Vercel project with the corresponding environment variables.

## Transport decision

The product no longer uses Alexa Proactive Events as a command channel. Amazon documents Proactive Events as customer notifications, while Alexa Messaging delivers out-of-session messages to a skill. Neither is a general-purpose API for injecting arbitrary remote-control actions into an Echo Show.

The production command path is:

`Echo Show Remote mobile app -> authenticated relay -> alexa-remote2 -> Amazon Alexa service -> target Echo`

The relay is intentionally a separate component because it needs the user's authenticated Alexa session and must maintain the Amazon connection from a trusted host.

## Supported commands in v1

Media: play, pause, play/pause, next, previous, rewind, fast-forward, stop.

Volume: set volume, volume up/down, mute.

Device: stop/power-stop, do-not-disturb.

Voice: send a text command to Alexa, or speak text on the selected Echo.

## Deliberately unsupported commands

Touchscreen navigation, arbitrary app launching, camera controls, display gestures, and other commands in the original UI are not represented as working merely because a button exists. They require a device-specific transport. The client and relay now reject unsupported commands instead of returning false success.

## Security model

- Production relay command access requires `RELAY_TOKEN` by default.
- Set `RELAY_TOKEN_REQUIRED=false` only for trusted LAN development.
- Amazon authentication material remains on the relay and is never sent to the mobile app.
- The cloud gateway requires its own server-side `RELAY_TOKEN` and forwards only an explicit allowlist of commands.
- Relay command requests are rate-limited and payload sizes are bounded.
- Relay errors no longer expose the Amazon initialization exception through the public health endpoint.
- No user-generated relay URL is accepted by the API, preventing basic SSRF abuse.
- Legacy synthetic Alexa OAuth and pairing endpoints are disabled.
- The relay should be deployed behind a private network, VPN, or authenticated tunnel rather than exposing port 8080 directly to the internet.

## Storage

The deprecated `@vercel/kv` SDK has been removed. Vercel's current storage path is a Redis integration such as Upstash Redis. The app uses `@upstash/redis` and accepts `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN`, with compatibility fallback to `KV_REST_API_URL` / `KV_REST_API_TOKEN` during migration.

## Required runtime configuration

### Relay host

- `ALEXA_COOKIE_JSON` — authenticated Alexa cookie JSON generated by `npm run setup:alexa`.
- `RELAY_TOKEN` — long random secret shared with the trusted app/gateway configuration.
- `RELAY_TOKEN_REQUIRED=true` — recommended production setting.
- Optional: `ECHO_DEVICE`, `VOLUME_STEP`, `AMAZON_PAGE`, `ALEXA_SERVICE_HOST`.

### Vercel

- `RELAY_URL` — private/secured relay URL.
- `RELAY_TOKEN` — same secret configured on the relay.
- `APP_ORIGIN` — production app origin when browser CORS restriction is desired.
- `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN` for promotion/admin storage.
- `ADMIN_PASSWORD` for the promotions admin endpoint.

### Mobile app

- `EXPO_PUBLIC_API_URL` — Vercel API origin for cloud mode.
- A relay token must be supplied through the app's secure configuration for direct relay use; never hard-code a production token into source.

## Deployment modes

### Local-first

Run the relay on a computer/NAS/Raspberry Pi on the same LAN as the Echo. The mobile app uses `mode: local`, the relay LAN address, and the relay token.

### Remote

Run the relay on an always-on host with secure remote connectivity and configure the Vercel gateway with `RELAY_URL` and `RELAY_TOKEN`. Cloud mode is intentionally explicit; there is no fake default Vercel URL.

## Release configuration

The Expo app is version `1.0.1`, iOS build `2`, Android version code `2`. The previous placeholder EAS project ID and fake store URLs were removed. A real EAS project ID should be created/linked before store builds are submitted.

## Amazon dependency

`alexa-remote2` uses Amazon's web/service interfaces rather than an official public Echo remote-control API. It is a third-party transport and can be affected by Amazon authentication or API changes. The relay isolates that dependency so it can be replaced without rewriting the mobile UI.

Amazon's official Alexa Smart Home APIs are appropriate when controlling a device that the product itself owns and exposes as a smart-home endpoint. They do not provide a generic API for controlling an arbitrary consumer Echo Show as though it were a TV remote.
